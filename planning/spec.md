# IT access-request specification

The intake and submission requirements draw from `CHALLENGE.md`, `docs/requirements.md`, `materials/office-policy.md`, `snapshot.schema.json`, and all 20 `materials/requests/IT-001.json`–`IT-020.json` exports. The [accessibility requirements](#section-508-accessibility) also draw from Section 508 of the Rehabilitation Act, codified at 29 U.S.C. § 794d, and the Revised 508 Standards. Each requirement occupies one physical table row and states one testable sentence. Source quotations use exact wording. Request-message quotes use decoded JSON strings, with line breaks rendered as `<br>` to keep one physical row. Schema sections use JSON pointers.

Validation entries are acceptance procedures, not claims that implementation or tests already exist. `tests/test_spec_contract.py` and its `test_rNN_contract` methods are proposed validation locations/names, not required application architecture. The named tests must be implemented and discovered before their commands count as validation: a run reporting zero tests does not satisfy a row. The existing starter tests in `tests/test_starter.py` check only supplied-file loading and a canned mock response. Run all implemented checks from the repository root with `env -u API_KEY python3 -m unittest discover -s tests -v`; each automated row also gives a targeted command. For manual rows, inspection and documented executable commands are the check; facilitator capture and Classroom checks occur at final submission. No application code, test implementation, commit, push or submission is requested by this document-writing task.

Inspection references to `intake/`, persisted records, operational logs and a dependency lockfile denote the implementation artifacts to inspect once chosen; their storage format and exact filenames are not specified by the sources. Only the source-mandated deliverable paths are fixed. Source-specific cases below instantiate the general extraction and routing rules and do not require exact prose wording for business purposes or issues beyond the source policy. Scalar expectations and routing tuples are exact; evidence quotes must be exact substrings.

## Section 508 accessibility

## Open questions and limits established by the sources

These are unresolved choices or missing thresholds, not additional requirements.

- **Workload and timing:** `docs/requirements.md` § Operating context / Workload and the review day says “around 200–400 request messages” and “roughly 2,000 messages” and requires completed work to remain available during preparation; it specifies no throughput, latency, concurrency count, retry budget or pass-rate target, so checks demonstrate supported behavior and record limits without inventing numerical guarantees.
- **Shared-operation mechanism:** § Shared operations requires coherent current records and trustworthy history when operators overlap but does not prescribe a database, lock, queue, deployment topology or number of worker processes; the implementation must document its supported arrangement and verify its coherence rather than silently assume overlap cannot happen.
- **Refresh identity and recovery representation:** § Updates and follow-up requires refresh for relevant configuration/policy changes and attribution to settings/policy versions, but does not enumerate fingerprint fields, mandate a version-ID encoding, prescribe history paths, specify automatic retry scheduling, or define a force-refresh CLI flag; those remain implementation choices subject to the stated reuse/history/current-error behavior.
- **Export metadata versus source facts:** `materials/office-policy.md` § Input export format resolves the export-date ambiguity: “the export timestamp describes when the record was exported”; it does not supply missing business dates, and “A relative date stays unresolved” in § Extracted facts prevents resolving IT-011 from a calendar.
- **Dates and schema:** `snapshot.schema.json` allows nullable strings for dates but defines no JSON Schema date format; the YYYY-MM-DD requirement comes from § Extracted facts, and reversed dates are a clarification issue under rule 3 rather than permission to change the explicit dates.
- **Business-purpose, issues and evidence wording:** Sources require explicit facts, explanatory issues and exact quote substrings, but define no canonical purpose summary, issue-code vocabulary, quote count, minimal quote span, normalization rules or accuracy denominator; the accuracy procedure must declare its comparisons without turning optional choices into source requirements.
- **Other messages:** IT-017 explicitly asks where the form is, supporting kind=other and clarification; its stated communications/onboarding purpose may be retained as source-derived purpose, but the source does not authorize inventing an access system, environment, permission, manager or access window.
- **Policy precedence:** § Review queue resolves override/withdrawal/missing-information precedence with “Apply these rules in order after validating the extraction”; IT-006’s attack is evidence rather than authority, IT-005 may have null nonessential fields, and IT-004/020 remain conflicts while IT-008/015 contain explicit corrections.
- **Human workflow:** Policy specifies the owner role and next action, including Security Review’s recommendation to the system owner, but supplies no individual system-owner directory or approval-system integration; named managers are contacts, and the requested output remains a review queue.
- **Interface and provider:** `CHALLENGE.md` permits a CLI, service or web application and the requirements mandate configurable model/provider settings and API_KEY, but no particular framework, SDK, provider, model, API version or live-call requirement is specified; live observations are optional and must be labelled when present.
- **Submission dependencies:** The challenge assigns Classroom and capture instructions to the facilitator; their details cannot be inferred from these files, and the final-submission requirements above do not authorize submitting or pushing during this specification-only task.
